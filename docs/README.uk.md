# Andrii Naumov: портфоліо (нотатки українською)

Англійський опис для GitHub лежить у [README.md](../README.md). Тут детальніше про те, як усе влаштовано.

Портфоліо на React + Vite (чистий JavaScript, без TypeScript) трьома мовами: EN, DE, UK.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173/
npm run build      # готовий сайт у папці dist/ (Vite + scripts/prerender.mjs)
npm run preview    # перевірити зібраний сайт локально
```

## Як це працює

**Hero: фабрика сайтів.** `FactoryScene.jsx` — ізометричний цех із low-poly блоків (`RoundedBox` з drei, м'яке світло `Environment` + `Lightformer` без файлів HDR, тіні). Конвеєр працює сам, незалежно від скролу:

1. **Розробка:** портальний "принтер" над стрічкою збирає з сирих кубиків сторінку, поруч монітор із кодом (`npm run build`).
2. **Автоматизація:** сторінки проходять тунель-сканер `auto.py`, на даху крутяться шестерні, кожна сторінка отримує синю позначку "перевірено", поруч блимає сервер.
3. **Запуск:** готові сторінки піднімаються в телефон, над ним маяк розсилає хвилі й мітку `● live`.

Камера ортографічна (ізометрія). Hero має висоту 360vh, вміст "прилипає" (`position: sticky`), ScrollTrigger рахує прогрес 0…1, і камера летить: загальний план → станція 1 → 2 → 3, між станціями трохи віддаляючись. Точки перемикання задані в `stageWeights()` і `VIEWS` у `FactoryScene.jsx`, підписи етапів вмикаються в тих самих точках (`STAGE_STARTS` у `Hero.jsx`). На широких екранах сцена праворуч від тексту, на телефоні — у вільному місці над текстом, і на станціях її боки можуть трохи виходити за край, щоб вона була більшою. Краї сцени м'яко зникають (CSS `mask-image` на `.hero__canvas`): під шапкою, над смужками етапів, ліворуч під текстом на ПК і над підписом етапу на телефоні. Тому підлога цеху ніколи не налазить на текст.

**Зміна мови.** `FlapText.jsx` розбиває заголовок на літери. Коли текст змінюється, кожна літера кілька разів перегортається (GSAP, `rotationX`) через випадкові букви і зупиняється на новій, як табло на вокзалі. Справжній текст лежить у прихованому `span` для скрінрідерів і SEO. Звичайний текст при цьому просто плавно з'являється (клас `is-switching` на `body`).

**Термінал.** Вивід зберігається не як готовий рядок, а як функція від `t()`, тому вся історія перекладається, коли змінюється мова.

**Мапа.** `scripts/build-map.mjs` один раз генерує сітку точок Європи з даних `world-atlas`. У цих даних (Natural Earth) Крим віднесено до Росії, тому скрипт примусово фарбує точки півострова як Україну. Маршрут — це SVG `path` з двох дуг, а `stroke-dashoffset` прив'язаний до скролу.

**Доступність.** Якщо в системі ввімкнено "зменшити рух" (`prefers-reduced-motion`), анімації вимикаються. 3D-сцена завантажується окремим файлом і не рендериться, коли hero поза екраном.

**Лоадер і завіса блокують сторінку.** Поки на екрані лоадер або завіса переходу, сторінку не можна прокрутити, клікнути чи відкрити термінал: `lockInteraction()` у `lib/motion.js` зупиняє Lenis і перехоплює колесо, дотики, клавіші й кліки. Кожен виклик повертає свою функцію `unlock`, і сторінка звільняється, коли розблокували всі.

**Плавність на слабких телефонах і повільному інтернеті.** Лоадер і завіса анімують тільки `transform` і `opacity` через CSS і Web Animations API (`element.animate`). Браузер виконує такі анімації окремо від JavaScript, тому вони не смикаються, навіть коли сторінка ще завантажується або за завісою будується нова сторінка. Лого для них (`GrowMark.jsx`) складене з HTML-блоків, обрізаних `clip-path`, бо частини SVG так анімувати не можна. 3D-сцена вмикається тільки після того, як лоадер зник (`loaderDone` у `lib/motion.js`): поки лоадер на екрані, з ним нічого не конкурує за головний потік. Поки сцена ще малюється, на її місці стрибають три блоки (`.hero__canvas-wait`), а коли вона дала перші кадри (`sceneReady`), canvas плавно проявляється. На телефонах сцена рендериться в трохи нижчій роздільності.

**Лоадер у статичному HTML.** Оскільки сторінка тепер рендериться на етапі збірки (див. нижче), у готовий HTML потрапляє лише порожня підкладка лоадера без лого. Якби туди потрапило й лого, React замінив би ці елементи своїми і CSS-анімація стартувала б з нуля — лого смикалося б. Тому перший кадр це просто колір паперу, а лого малюється один раз, коли змонтувався React. У підкладки зі статичного HTML (`.loader[data-static]`) є запобіжник: якщо JavaScript не прийшов узагалі, вона сама згасає через 4 секунди і показує сторінку.

**3D на телефоні** займає все вільне місце між шапкою і текстом: `Hero.jsx` вимірює, де починається текст, а сцена підбирає масштаб під кожен етап. Коли заголовок зникає і лишається короткий підпис етапу, модель стає більшою.

**Картинки** лежать окремими файлами в `public/`: `favicon.svg` (з версією для темної вкладки браузера) і `apple-touch-icon.png` для іконки на головному екрані iPhone. Лого в шапці, лоадері й завісі — це компонент `LogoMark.jsx`, бо його частини анімуються окремо.

**Термінал.** Відкривається і закривається клавішею ліворуч від "1" на будь-якій розкладці: перевіряється фізична клавіша (`e.code === 'Backquote'`), а не символ. Тому працює і з українською (`'`), і з німецькою (`^`). Вікно терміналу прокручується колесом миші окремо від сторінки (атрибут `data-lenis-prevent`).

**Адреси й мови.** Німецька живе в корені: `/`, `/impressum`, `/datenschutz`. Англійська й українська мають префікс: `/en`, `/uk/impressum` тощо. Усі сторінки обробляє один маршрут (`Shell` в `App.jsx`), тому при зміні мови сторінка не перезавантажується: 3D-сцена і позиція скролу зберігаються.

**Визначення мови** (`lib/lang.js`). Коли людина вперше відкриває німецьку адресу без префікса, сайт по черзі перевіряє:

1. мову, яку вона вже обирала перемикачем (зберігається в `localStorage`);
2. мови браузера в порядку пріоритету;
3. часовий пояс пристрою (Київ → українська, Берлін, Відень, Цюрих → німецька);
4. якщо нічого не підійшло, залишається німецька.

Перенаправлення відбувається ще до першого рендеру, тому нічого не блимає. Посилання з явною мовою (`/en`, `/uk`, `/de`) завжди відкриваються як є. Жодних запитів до сторонніх API немає, тож для GDPR тут нічого додатково описувати не треба. Для пошуковиків додаються теги `hreflang`.

**Переходи між сторінками** (`lib/routing.jsx`). Посилання на Impressum, Datenschutz і назад ведуть через `TransitionLink`: знизу піднімається темна завіса, в ній "виростає" лого, під нею відкривається нова сторінка (вже прокручена вгору), і завіса йде вгору. Кнопки браузера "назад/вперед" показують другу половину переходу. Зміна мови завісу не показує, бо сторінка та сама.

**Кейси клієнтів** (`Projects.jsx`). Сайти, зроблені на фрилансі (переважно зі студією Apex Webcraft), показані у вікні браузера зі справжнім скріншотом; при наведенні скріншот повільно прокручується вниз сторінки. Тексти — у `projects.cases` у файлах мов, посилання й пропорції скріншотів — у `CASES` у `src/data/site.js`, самі скріншоти — у `public/projects/` (`<id>.webp` 1240 px і `<id>-620.webp`). Щоб додати кейс: скріншот 16:10 або вищий, запис у `CASES` і текст у трьох мовах.

Внутрішній інструмент (парсер) показаний так само, але без посилань: у `CASES.parser` замість `url` стоїть `host: 'localhost:4173'`, прапорець `nda: true` і масив `shots` з пропорціями трьох скріншотів — під вікном зʼявляються мініатюри, які перемикають знімок.

**Мапа в "Шляху".** Після останнього пункту таймлайну є вільне місце (`padding-bottom` у `_journey.scss`), тож мапа залишається на екрані, поки Гаген загоряється, і з'являється підпис "Тепер я вдома в Гагені".

## Що лишилось

1. **Німецькі тексти** (`src/locales/de.json`) дай перевірити носію мови.
2. **Беклінки:** посилання на сайт у профілях LinkedIn і GitHub, у CV, у підписі пошти.
3. **Google Search Console:** додати сайт і згодувати `sitemap.xml`.
4. Якщо зʼявиться свій домен — поміняти `SITE_URL` у `src/data/site.js`, решта (canonical, hreflang, sitemap, og:image) перебудується сама.

Impressum, телефон, CV німецькою і `SITE_URL` уже заповнені.

**Форма звʼязку** (`ContactForm.jsx` + `worker/index.js`). Форма шле JSON на `POST /api/contact`; цей маршрут обробляє Cloudflare Worker і пересилає повідомлення в Telegram-бот. Ні поштового сервера, ні стороннього сервісу форм, нічого не зберігається в базі. Від ботів захищають приховане поле-пастка (будь-що в ньому — бот) і мінімальний час заповнення 3 секунди, плюс перевірка `Origin` і обмеження довжини полів. Токен бота ніколи не потрапляє у відповідь. Форма описана в політиці конфіденційності (розділ 4) — у Німеччині це обовʼязково.

**Сторінка 404** (`pages/NotFound.jsx`). Невідома адреса більше не перекидає тихо на головну: Cloudflare віддає `404.html` зі статусом 404, адреса лишається в рядку, і відвідувач бачить, що саме не так, з кнопками на головну і до проєктів. Мова береться з префікса адреси, тому `/en/щось-не-те` відкриється англійською.

**Підказка про термінал** (`TerminalHint.jsx`). Зʼявляється один раз на браузер, через 10 секунд після того, як сторінка готова, і живе 14 секунд. Тільки там, де є клавіатура (`hover: hover and pointer: fine`), щоб не заважати на телефоні. Згода запамʼятовується в `localStorage`.

## Деплой на Cloudflare

Проєкт підключений у Cloudflare як Worker зі статичними файлами (Workers & Pages → Create → Import a repository):

- Build command: `npm run build`
- Deploy command: `npx wrangler deploy`
- Build variable: `SITE_URL` = `https://твій-домен` (без слеша в кінці)

`wrangler.jsonc` у корені каже Cloudflare віддавати папку `dist/`: `/en` відкриває `en.html`, невідомі адреси отримують `404.html`. Версію Node бере з `.node-version` (20). Кожен пуш у `main` перезбирає сайт. Свій домен підключається у вкладці **Domains** (або Settings → Domains & Routes → Custom domain).

### Секрети для форми

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
```

Токен бере бот-батько в Telegram, id чату підкаже бот, який показує інформацію про користувача. Або в дашборді: Workers → проєкт → Settings → **Variables and Secrets** (саме там, а не в Build variables — ті доступні лише під час збірки). Локально: скопіюй `.dev.vars.example` у `.dev.vars`. Без секретів маршрут відповідає `503`, і форма показує пошту як запасний варіант. Боту треба один раз написати `/start`, інакше Telegram не дасть йому писати тобі першим.

### Що робить збірка

`scripts/prerender.mjs` після `vite build` **рендерить увесь застосунок у HTML** (`renderToStaticMarkup` + `StaticRouter`) для кожної адреси. Без цього пошуковики й перевірялки бачили порожній `<div id="root">`: нуль слів, нуль заголовків, нуль посилань. Тепер у статичному HTML близько 1100 слів, H1, пʼять H2, внутрішні посилання і лендмарки `header`/`main`/`footer`.

React у браузері цю розмітку **не гідратує, а перемальовує** (`createRoot`), тому розбіжність (годинник у контактах, випадкові літери в табло) нічого не ламає.

Щоб рендер проходив у Node, кілька місць знають про відсутність браузера: `i18n.js` не визначає мову з `window`, `Journey.jsx` не вимірює SVG-шлях і не малює 3562 точки мапи (це 180 КБ на сторінку, і пошуковику вони ні до чого), `Hero.jsx` не перевіряє WebGL, `Loader.jsx` не малює лого.

Крім HTML, збірка створює `404.html` (справжня сторінка «не знайдено», `noindex`), `robots.txt` і `sitemap.xml`, а також додає `modulepreload` для чанка 3D-сцени і `preload` для двох критичних шрифтів потрібної абетки.

У `public/` лежать файли для Cloudflare:

- `_headers` — заголовки безпеки (CSP, HSTS, заборона вбудовувати сайт у чужі iframe) і довгий кеш для `/assets/*`;
- `_redirects` — `/de/...` веде на корінь, `/en/` на `/en`.

У Cloudflare не вмикай Web Analytics, Rocket Loader і Zaraz: сайт обіцяє в Datenschutz, що нічого не відстежує, а CSP заблокує чужі скрипти. Якщо колись захочеш аналітику, треба оновити і політику конфіденційності, і CSP.

Перевірити збірку локально так, як її віддасть Cloudflare: `npm run build`, потім `npx wrangler dev`.
